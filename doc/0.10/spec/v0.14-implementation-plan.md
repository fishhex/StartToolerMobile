## 范围声明（v0.14 App 重构）

- **平台**：Android only。iOS / macOS 暂不考虑。
- **UI**：不考虑。用最朴素 Material 默认组件，按钮 + 输入框 + 列表 + 文字提示即可，无设计 tokens / 无主题 / 无动效。
- **发现入口**：**真相机扫码（mobile_scanner）作为 QR 唯一入口**（KB §一明令"QR 唯一"）。不提供粘贴文本框 / 手动输入 IP 等兜底入口。
- **真实实现**：全部 HTTP 客户端直连 PC 端真实 HTTP 接口，**不使用 mock 数据**。开发期联调可启本地 Python `aiohttp` mock server（不进代码库）。测试用 `package:http/testing.dart` 的 `MockClient` 注入桩。

## 第一期任务拆分（4 个 task）

| Task | 主题 | 关键交付 |
| --- | --- | --- |
| **T1** | 路由 + 4 页面骨架 + **扫码页（mobile_scanner）** + QR 解析 + health 客户端 | 路由（go_router） + 4 页面（connect/扫码 / home / settings） + 相机权限 + QR 解析纯函数 + health 客户端（直连真实 PC） + `AppErrorBus` 错误总线占位 |
| **T2** | projects 客户端 + 持久化（EncryptedSharedPreferences）+ 空间列表 + 启动续连 | `projects_api.dart`（直连真实 PC） + `secure_store.dart` 封装 + `Space` 模型 + 空间列表 UI + 启动逻辑：读持久化 → health 验证 → 跳页 |
| **T3** | 上传流程（Photo Picker + multipart + 进度 + 失败分桶） | Photo Picker + multipart 客户端 + 进度条 + 失败 SnackBar + 客户端扩展名预过滤 |
| **T4** | 错误处理 + 状态机 + i18n + 端到端验收 | 全局错误总线收敛 + 401/网络错误映射 + 状态机重整 + i18n strings + 验收清单逐项跑 + 性能验收 |

**T1-T3 内部仍按依赖推进**：T1 是地基（扫码 + QR 解析 + health），T2 接入持久化+空间列表（依赖 T1 的 health/路由），T3 上传（依赖 T1 的 health + T2 的持久化）。T4 收尾所有横切关注点 + 验收。

## 依赖关系

```
T1 ─→ T2 ─┐
    └─→ T3 ─→ T4(端到端验收)
```

- **T1**：骨架 + 扫码 + QR 解析 + health 客户端 + 4 页面。**不接持久化**，主页项目数据先用硬编码一个「当前空间」用于跳转演示。
- **T2**：projects 客户端 + 持久化 + 空间列表 + 启动续连。**接 T1 的 health 与路由**。
- **T3**：上传流程。**接 T1 的 health + T2 的持久化**。
- **T4**：错误处理/状态机/i18n/验收。

## 跨期预留抽象（T1 即定型）

- **`QrParser`**：QR 文本 → `{ host, port, secret }`。扫码结果唯一消费者。
- **`SecureStore` 接口** + Android EncryptedSharedPreferences 实现。
- **`AppError` / `AppErrorBus`**：统一错误类型 + 顶层 banner 显示。
- **`Space` 数据类**：name / ip / port / secret / lastSeenAt。

## 真实实现约束

- 所有 HTTP 客户端直连 PC 端 `/api/v1/*` 接口，无 mock 兜底。
- **开发期联调依赖**：PC 端 v0.14 服务（`StartTooler/Services/UploadServerService.cs`）必须运行；或本地 Python `aiohttp` mock server 实现 `/api/v1/health` + `/api/v1/projects` + `/api/v1/projects/{name}/upload` 三个端点。该 mock server 仅供开发联调，**不进 App 代码库**。
- **测试**：使用 `package:http/testing.dart` 的 `MockClient` 注入测试桩。

## 扫码（QR 唯一入口）

- 库：`mobile_scanner`（CameraX + ML Kit Barcode 封装，Android only）。
- 入口：`/connect` 页打开后立即调起相机（无需中间按钮）。
- 权限：AndroidManifest 加 `<uses-permission android:name="android.permission.CAMERA" />`；首启动态申请。
- 流程：扫码 → 解析 QR 文本（`QrParser`）→ 校验合法 → 调 health → 写持久化 → 跳 `/home`。
- 失败 UX：扫描框一直显示；非法 QR → 顶部 banner 提示「二维码无效」（不关闭扫码页）。
- **不做**：粘贴文本框、手动输入 IP 兜底入口、扫码后多 QR 候选选择。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| PC 端 v0.14 未落地 | T1+ 联调阻塞 | 本地 Python `aiohttp` mock server 实现三端点（不进代码库），用于 App 端独立调试 |
| 扫码权限被拒 / 设备无相机 | T1 阻塞 | 首启检测权限；权限被拒 → 顶部 banner「需要相机权限才能扫码」+ 提供「去设置」入口 |
| 错误处理分散到 T1-T3 各处 | T4 返工 | T1 即用统一 `Result<T, AppError>` 返回类型 + `AppErrorBus` 注入；T4 仅做收敛，不需大改 |
| 端到端性能（扫码 → 上传完成）| §十六验收 | T3 末做性能 profile，重点看扫码识别时延 + health 超时 + multipart 串行上传 |
| 持久化封装跨平台预留 | 仅做 Android 时过度设计 | T2 仅实现 Android EncryptedSharedPreferences；iOS/macOS 接口留 TODO 不实现 |
