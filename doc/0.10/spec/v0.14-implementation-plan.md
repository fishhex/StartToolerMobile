## 范围声明（v0.14 App 重构）

- **平台**：Android only。iOS / macOS 暂不考虑。
- **UI**：最简实现。Material 默认组件，无自定义 design tokens、无自定义主题、无背景动效。后续如有需要再迭代。
- **发现入口**：M3 优先用「粘贴 QR 内容」文本框跑通主流程，真相机扫码留作可选项（不在本期分期）。
- **真实实现**：全部功能直连 PC 端真实 HTTP 接口。**不使用 mock 数据**；测试期由本地 Python mock HTTP server 提供响应（仅作为测试替身，不进生产代码）。

## 依赖关系

```
M1 ─┬─→ M2 ─→ M3 ─→ M4 ─→ M5 ─→ M7
    │       │       │
    └─ 骨架 ─┴─ 持久化 + 扫码 ─┴─ 上传 + 错误 + 验收
```

- **M1** 是地基（路由 + 5 个空页面 + QR 解析纯函数 + health/projects 客户端）。所有后期依赖。
- **M2** 在 M1 主页就绪后接入持久化层；M3 之前需要持久化能写入新空间。
- **M3** 首次端到端"粘贴 QR → 主页"打通，需 PC 端 v0.14 服务运行。
- **M4** 主页有项目数据后做上传；不依赖 M3（手动选空间也可触发上传）。
- **M5** 横切关注点，放在 M4 之后一次收敛（避免早期错误处理分散到各处）。
- **M7** 全量验收 + PC 端 v0.14 联调。

## 跨期预留抽象（M1 即定型）

- **平台差异抽象**：`SecureStore` 接口在 M1 末定签名，M2 实现 Android 端（iOS 端接口保留但暂不实现）。
- **错误总线**：`AppErrorBus` 在 M1 末引入并接入主页（哪怕暂时只有一个网络错误），M5 收敛全量错误码。
- **持久化模型**：`Space` 数据类 M1 末定义只读字段，M2 加密落地。

## 真实实现约束

- 所有 HTTP 客户端直连 PC 端 `/api/v1/*` 接口，无 mock 兜底。
- **开发期联调依赖**：
  - PC 端 v0.14 服务（`StartTooler/Services/UploadServerService.cs`）必须运行；
  - 或本地 Python `aiohttp` 启一个 mock server 实现 `/api/v1/health` + `/api/v1/projects` + `/api/v1/projects/{name}/upload` 三个端点，用于在没有真 PC 端时验证 App 端逻辑。**该 mock server 仅供开发联调，不进 App 代码库。**
- **测试**：使用 `package:http/testing.dart` 的 `MockClient` 注入测试桩（这是测试替身，不是 mock 数据）。

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| PC 端 v0.14 未落地 | M1+ 联调阻塞 | 本地 Python `aiohttp` mock server 实现三端点（不进代码库），用于 App 端独立调试 |
| 「粘贴 QR」流程体验差 | 用户测试不便 | 仅做开发期快速验证；真相机扫码留作可选延后项 |
| 错误处理分散 | M5 返工大 | M1 起即用统一 `Result<T, AppError>` 返回类型，M5 收敛错误总线时不需大改 |
| 端到端性能（粘贴 → 主页）| §十六验收 | M3 末做性能 profile，重点看 health 超时 |
